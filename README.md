# מרווח — מקום למחשבה אחרי הפגישה

פורטל הדגמה בעברית לתיעוד של מטפל אחרי כל פגישה. המטפל פותח תיק בדיוני חדש או בוחר תיק קיים ופגישה, משתף בחופשיות בשיחה אמיתית עם מודל שפה, ועובר לכל היותר שלוש שאלות פתוחות המעוגנות במה שכתב לפני טיוטה. הבינה מציעה גם עדכונים להמשגה, לאינטייק, לחומרי הלמידה ולהכנה להדרכה. אישור מפורש מכניס את כל חמשת התוצרים לתיק יחד; השיחה וההצעה נשמרות בנפרד כהמשך עבודה עד האישור. אפשר לעיין ולערוך אותם ישירות, עם מקורות וגרסאות מלאות.

**זהו אבטיפוס עם דמויות ונתונים מומצאים מאפס. אין להזין מידע של מטופלים אמיתיים.** בחינת התאמה לעבודה קלינית אמיתית דורשת מערכת אחסון, הרשאות, אבטחה ובדיקה מקצועית נפרדות; הדמו אינו מציג עצמו כפתרון קליני מאושר.

## פתיחת תיק ושמירה בין מכשירים

לחצו **תיק חדש**, הזינו שם תצוגה או קוד בדיוני, ובמידת הצורך יום ושעה קבועים. אלה פרטי הפתיחה היחידים; אין שאלון קליטה או דרישה לגיל, אבחנה או רקע. נפתחים רצף מקורי ופגישה 1. בחירה בתיק קיים פותחת את הפגישה האחרונה שלו, בלי ליצור פגישה חדשה מעצם הבחירה; בחלון ההיכרות בוחרים במפורש להמשיך פגישה פתוחה או לפתוח את הבאה לאחר אישור הקודמת. המועד הקבוע הוא תכנון שבועי בלבד, ללא תזכורת או אישור שפגישה התקיימה.

האתר נפתח במסך **כניסה למערכת**, עם שם משתמש וסיסמה פרטית. ברירת המחדל לשם המשתמש היא `elad`; הסיסמה אינה מופיעה במאגר או בספר. אחרי הכניסה נפתח חלון **מכירים את התיק, ואז מתחילים**, המציג את הדמויות הבדיוניות, קטעים מהפגישות הקודמות והחומרים שכבר קיימים. ההיסטוריה נכתבה מראש; השאלות והטיוטות החדשות מופקות במודל שפה. שליחת הודעה מפעילה תגובה, ובכפתור **איך נוצרה התגובה?** אפשר לפתוח הסבר: מקור התגובה, ההקשר, הסבר קצר והעדכונים שהוחזרו. אין מתג למצב מוכן ואין החלפה אוטומטית לתשובה מוכנה.

הכניסה טוענת אוטומטית את מרחב התיקים מהשרת. כל התוכן המתמשך נשמר ב־Neon; הדפדפן מחזיק רק את העבודה הפעילה בזיכרון. פרטי הכניסה פותחים מרחב עבודה אחד, ללא הרשאות נפרדות לכל תיק. שמירת המאגר אינה מפעילה מודל בתשלום.

המתינו לסימון **נשמר בשרת** לפני סגירה. אחרי רענון נכנסים שוב והשרת מחזיר את התיקים, השיחות, הטיוטות והגרסאות. כשל שמירה מוצג במפורש; העבודה שטרם נשמרה נשארת בזיכרון העמוד וניתנת לניסיון חוזר או לייצוא יזום. אין שמירת תוכן אוטומטית בדפדפן ואין דריסה שקטה של עבודה ממכשיר אחר.

## הפעלה מקומית

להפעלה ראשונה השתמשו ב־Node.js 24 וב־npm. זהו גם ה־major שנבחר ב־CI של הפרויקט; Vite הנעול דורש בפועל `^20.19.0 || >=22.12.0`, ולכן Node 22.0 אינו מספיק.

```sh
git clone https://github.com/elad-refoua/iser-clinician-portal.git
cd iser-clinician-portal
npm ci
npm run dev
```

פתחו את הכתובת שמדפיס Vite, בדרך כלל `http://127.0.0.1:5173`. מסך הכניסה נטען גם לפני הגדרת שרת; שימוש במערכת דורש API עם אימות, ושיחה חדשה דורשת גם ספק מודל. `npm run dev` מפעיל את הממשק בלבד; אין בו שרת `/api` מקומי אוטומטי.

לחיבור לשרת חי משלכם, צרו **`apps/web/.env.local`**, עם שורה זו לאחר החלפת הדומיין:

```dotenv
VITE_API_URL=https://YOUR-API-PROJECT.vercel.app
```

הקובץ `.env.example` בשורש מפרט את שמות ההגדרות; קובץ `.env.local` בשורש **אינו** נקרא על ידי תצורת Vite הנוכחית, ששורשה `apps/web`. אין להעתיק סודות שרת לקובץ הממשק. הפעילו מחדש את Vite לאחר שינוי. `VITE_API_URL` הוא מקור ציבורי בלבד, ללא `/api` בסופו; מפתח ספק לעולם אינו משתנה `VITE_`.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

בדיקות רגילות אינן שולחות קריאות בתשלום. `API_BUDGET_LIVE=1` מפעיל בדיקת קטלוג מודלים ציבורי בלבד; אינו מפעיל שיחה. בדיקות שיחה חיה נעשות במפורש ובתוך המכסות.

להפקת ספר ההפעלה ראו [הוראות הבנייה](docs/handbook/README.md). יש לבנות HTML ו־PDF יחד לפני פרסום שינוי במקור או בפרומפטים; בניית האתר לבדה אינה מעדכנת את הספר.

## התקנת עותק עצמאי

הכתובות בראש README שייכות לדמו המקורי. לפריסה עצמאית משתמשים בחשבונות GitHub ו־Vercel שלכם. בנייה ובדיקות מקומיות אינן דורשות סודות; כניסה לממשק דורשת API מאומת עם Upstash Redis, ושיחה חדשה דורשת OpenRouter. אין מסלול שיחה מוכן שאפשר להפעיל בלי שרת. Neon Postgres נדרש למסלול הכניסה המלא, שפותח ושומר את התיקים בין מכשירים. ההסברים הבאים משתמשים בשמות `ACCOUNT`, `REPOSITORY` ו־`YOUR-API-PROJECT` כמצייני מקום שיש להחליף.

### 1. מאגר ופרויקט Vercel

צרו Fork של מאגר זה בחשבון GitHub שלכם ושכפלו את ה־Fork לפיתוח. ב־Vercel בחרו **Add New → Project**, ייבאו את המאגר שלכם, והשאירו **Root Directory בשורש המאגר** — לא `apps/web` ולא `api`. בחרו שם פרויקט זמין משלכם והגדירו את ענף הייצור לפי המאגר, כאן `main`. שמות וחשבונות מקומיים מקובץ `.vercel` של מחשב אחר אינם חלק מההתקנה. [תיעוד ייבוא Vercel](https://vercel.com/docs/git).

`vercel.json` מגדיר Vite, פקודת `npm run build`, תוצר `dist`, אזור `fra1` ו־60 שניות לפונקציות `api/*.ts`. בחרו Node.js 24 בהגדרות הפרויקט. אין להגדיר `PAGES_BASE` בפרויקט Vercel: שם הממשק מוגש בשורש `/`. הגדרות Production צריכות לאפשר גישה ציבורית ל־API מהדפדפן, תוך השארת קוד הגישה של האפליקציה פעיל.

### 2. Redis וסודות שרת

צרו מאגר Upstash Redis ייעודי לסביבת הדמו, ישירות ב־Upstash או דרך אינטגרציית Vercel. דרושים **כתובת HTTPS של REST ואסימון כתיבה רגיל**, ולא כתובת TCP מסוג `redis://` או אסימון read-only. הקוד מפעיל `PING` ו־`EVAL` של Lua שכותבים מונים, hashes, נעילות ומועדי תפוגה. בדיקת PING בלבד אינה מוכיחה שהאסימון יכול לשמור מכסות. [תיעוד REST](https://upstash.com/docs/redis/features/restapi), [תמיכת Lua](https://upstash.com/docs/redis/sdks/ts/commands/scripts/eval).

השתמשו במאגר ייעודי או במרחב שמיועד רק לפרויקט: קידומת המפתחות קבועה `iser:v1:`. שיתוף אותו Redis בין עותקים יוצר תקציב כולל משותף. אל תגדירו eviction של מפתחות מכסה ואל תמחקו או תאפסו קבלות כדי לעקוף מגבלה. בחרו תוכנית שירות ומגבלות הוצאה משלכם; מכסות קוד המודל אינן מגבלות החיוב של שירות האירוח או Redis.

ב־Vercel → Settings → Environment Variables הגדירו את המשתנים הבאים ל־**Production**, בלי מירכאות סביב הערך ובלי ירידות שורה מיותרות. שינוי משתנה דורש פריסה חדשה כדי להיכנס לבנייה/פונקציה החדשה. [תיעוד סביבות Vercel](https://vercel.com/docs/environment-variables).

| שם | פורמט נדרש |
|---|---|
| `OPENROUTER_API_KEY` | מפתח OpenRouter מוגבל תקציב; שרת בלבד |
| `DEMO_USERNAME` | שם המשתמש לכניסה; ברירת המחדל `elad`. אפשר לבחור שם לעותק שלכם |
| `DEMO_ACCESS_CODE_HASH` | בדיוק 64 תווי hex של SHA-256 לסיסמה הפרטית, ולא הסיסמה עצמה; שם המשתנה נשמר לתאימות |
| `SESSION_SECRET` | מחרוזת אקראית של 32 תווים לפחות |
| `KV_REST_API_URL` | כתובת HTTPS של REST עבור Redis |
| `KV_REST_API_TOKEN` | אסימון Redis עם הרשאת כתיבה והרצת הסקריפטים |
| `ALLOWED_ORIGINS` | למשל `https://ACCOUNT.github.io,http://127.0.0.1:5173` |

חלופה מלאה ל־`KV_REST_API_URL` ו־`KV_REST_API_TOKEN` היא `UPSTASH_REDIS_REST_URL` ו־`UPSTASH_REDIS_REST_TOKEN`. הגדירו זוג אחד שלם. אם שני הזוגות קיימים, כל שם `UPSTASH_` מקבל קדימות, גם אם הוא ריק או שייך למאגר אחר. אל תערבבו כתובת של מאגר אחד ואסימון של אחר.

ערכי `ALLOWED_ORIGINS` הם origins ללא נתיב וללא `/` בסוף, מופרדים בפסיקים: `https://ACCOUNT.github.io`, לא `https://ACCOUNT.github.io/REPOSITORY/`. כתובת `localhost` שונה מ־`127.0.0.1`; פורט preview הוא בדרך כלל 4173 ויש להוסיפו במפורש אם בודקים ממנו מצב חי. אין wildcard. מקור ה־API עצמו מותר אוטומטית בקוד.

### 3. Neon לשמירת התיקים

לשמירה בין מכשירים צרו מאגר Neon משלכם, דרך **Storage / Marketplace → Neon** בפרויקט Vercel או בחשבון Neon שלכם. אפשר לבחור בתוכנית Free הזמינה ולחבר את המשאב ל־Production. בחרו אזור קרוב לפונקציות, למשל Frankfurt כאשר הפונקציות ב־`fra1`. בדקו את מגבלות התוכנית במסך השירות; מגבלת הדמו אינה התחייבות לאחסון חינם או זמין ללא הגבלה. [אפשרויות אחסון Vercel](https://vercel.com/docs/storage), [מנהל ההתקן של Neon](https://neon.com/docs/serverless/serverless-driver).

| משתנה שרת | משמעות |
|---|---|
| `DEMO_DATABASE_URL` | מחרוזת חיבור פרטית מסוג `postgresql://` או `postgres://`, עם משתמש, סיסמה, שרת ושם מסד, כפי שמספק Neon |
| `DATABASE_URL` | חלופה כש־`DEMO_DATABASE_URL` אינו מוגדר או ריק; אין צורך להגדיר את שניהם |
| `DEMO_WORKSPACE_ID` | מזהה קבוע של מרחב העבודה, עד 160 תווים; ברירת מחדל `owner-demo` |

אם האינטגרציה מציעה קידומת למשתנים, אפשר לבחור `DEMO_` ולוודא שנוצר בדיוק `DEMO_DATABASE_URL`. אם נוצר שם אחר, הגדירו אחד השמות שהקוד קורא. אל תוסיפו `VITE_`, אל תכניסו מחרוזת חיבור ל־GitHub Pages, ואל תדפיסו אותה בלוג. פרסו מחדש אחרי שינוי ההגדרות. לכניסה ולהפעלה מלאה יש להגדיר Neon: הממשק ממתין לפתיחת המאגר לאחר אימות פרטי הכניסה. אין מסלול עבודה מתמשך ללא שרת מאגר תקין.

השרת משתמש ב־`@neondatabase/serverless` דרך HTTPS. הקוד ב־`apps/api/workspace-store.ts` יוצר בפנייה הראשונה את הטבלה `public.merhav_demo_workspaces` בתוך טרנזקציה עם נעילה. משתמש המסד צריך הרשאות ליצירה בסכמה ולקריאה, הוספה ועדכון בטבלה. אין קובץ SQL נפרד להרצה או פקודת migration ידנית במהדורה הזו; ה־DDL נמצא בקובץ זה. מחרוזת PostgreSQL גנרית של שרת שאינו תואם לנתיב HTTP של Neon אינה תחליף מאומת.

שמרו את `DEMO_WORKSPACE_ID` קבוע גם בעת החלפת קוד הגישה. הוא אינו נגזר מהקוד; שינויו בוחר שורה אחרת ועלול להציג מרחב ריק, בלי למחוק את השורה הקודמת. כל האסימונים התקפים בפרויקט מגיעים לאותו מרחב. לסביבות Preview נפרדות השתמשו במסד או במזהה מרחב נפרדים כדי לא לשנות בטעות את מרחב Production.

### 4. יצירת סיסמה פרטית וחומר חתימה

הפקודה הבאה עובדת ב־PowerShell ובמעטפות POSIX עם Node מותקן. היא יוצרת קובץ פרטי בתיקייה מתוארכת תחת `.local` המוחרגת מ־Git, ואינה מדפיסה את הסודות. אין להריץ אותה כחלק מ־CI או לשמור את הקובץ במאגר:

```sh
node -e "const fs=require('node:fs'),c=require('node:crypto');const dir='.local/setup_'+new Date().toISOString().replace(/[:.]/g,'-');fs.mkdirSync(dir,{recursive:true});const code=c.randomBytes(24).toString('base64url');fs.writeFileSync(dir+'/credentials.json',JSON.stringify({DEMO_ACCESS_CODE:code,DEMO_ACCESS_CODE_HASH:c.createHash('sha256').update(code,'utf8').digest('hex'),SESSION_SECRET:c.randomBytes(48).toString('base64url')},null,2),{flag:'wx',mode:0o600});console.log('Created '+dir+'/credentials.json; values were not printed.');"
```

פתחו את הקובץ **מקומית ובפרטיות**. הזינו ב־Vercel את ה־hash ואת `SESSION_SECRET`; `DEMO_ACCESS_CODE` בקובץ שנוצר הוא הסיסמה שמקלידים בממשק, ולא משתנה שרת שנדרש בקוד. הגדירו גם `DEMO_USERNAME` אם תרצו שם שונה מ־`elad`. שם המשתמש נבדק ללא הבדל בין אותיות גדולות לקטנות; הסיסמה נבדקת בדיוק כפי שהוקלדה. אין צורך לחשב hash נוסף או לצרף ירידת שורה. החלפת ה־hash או חומר החתימה מבטלת אסימונים קיימים. קוד חדש אינו מאפס את התקציב הכולל של Redis.

### 5. פריסה ובדיקה ללא inference

אחרי הגדרת הסביבה, פרסו מ־Vercel או מה־CLI שלכם. אם בוחרים CLI, הפקודות אינן כוללות חשבון או מזהה פרויקט של המחבר:

```sh
npx vercel login
npx vercel link
npx vercel env ls production
npx vercel --prod
```

ב־`link` בחרו את החשבון והפרויקט שיצרתם. ב־`https://YOUR-API-PROJECT.vercel.app/api/models` אמור להתקבל JSON, ולא דף כניסה או דף HTML. השדות `readiness.providerKey`, `readiness.access`, `readiness.quota` מפרידים בין תצורת מפתח, אימות ו־Redis. `liveReady=true` מבטא תנאי מוכנות ראשוניים: הוא אינו מאמת את תקפות מפתח OpenRouter, אינו בודק הרשאת EVAL/כתיבה ואינו מוכיח שכל שלושת המודלים נגישים לבקשת inference.

לבדיקת המאגר היכנסו בשם המשתמש ובסיסמה, המתינו לפתיחת התיקים, צרו תיק בדיוני והמתינו ל־**נשמר בשרת**. פתחו את אותו אתר בדפדפן נפרד, התחברו במפורש, ובדקו שהתיק, המקורות והגרסאות נטענו. מאגר ריק מתחיל בגרסה 0; החיבור הראשון שומר בו את דמויות הבסיס הבדיוניות, ורק לאחר אישור השמירה נפתחת סביבת העבודה. `/api/models` אינו בודק Neon: זמינות המודל ושמירת המאגר הן בדיקות נפרדות.

`/api/access` מקבל JSON בצורה `{username, password}`, מפעיל הגבלת כניסה ב־Redis ומנפיק אסימון לשעה. הפורמט הישן `{code}` אינו מתקבל. הכניסה ושמירת המאגר אינן מפעילות inference. שליחת הודעה או בקשת טיוטה בודקות פנייה למודל ויכולות לצרוך תקציב. בדקו בנפרד כל מודל שעליו תרצו להכריז כתומך.

### 6. GitHub Pages בעותק שלכם

במאגר שלכם פתחו **Settings → Pages → Build and deployment → Source → GitHub Actions**. תהליך העבודה כבר נמצא ב־`.github/workflows/pages.yml`; אין צורך להוסיף workflow דוגמה נוסף. [הנחיות GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

עדכנו בו את `PAGES_BASE` ל־`/REPOSITORY/` ואת `VITE_API_URL` למקור ה־API שלכם. עבור אתר משתמש/ארגון המוגש בשורש או דומיין מותאם שמוגש בשורש, הבסיס הוא `/`. ודאו שענף ההפעלה מתאים לענף הראשי של ה־Fork. `PAGES_BASE` נקרא מ־`process.env` בזמן בניית Vite: ההגדרה ב־workflow או בסביבת המעטפת היא שקובעת; שורה בקובץ dotenv אינה מחליפה אותה בתצורה הנוכחית.

ה־workflow בונה ב־Node 24, מריץ בדיקות ומעלה את `dist`, עם הרשאות `contents: read`, `pages: write`, `id-token: write`. הוא מעתיק את ספר ההפעלה שנבנה ושמור במאגר, ואינו מרנדר PDF מחדש. אחרי דחיפה ל־main בדקו את ריצת Actions ואת האתר הציבורי, לרבות קישורי הספר, כניסה חיה ו־CORS מהמקור החדש. התאימו גם את הקישורים והמטא־נתונים של הספר לעותק שלכם לפני פרסום שלו.

השרת מסרב להפעלה חיה אם שירות המכסות אינו זמין. Redis שומר **מטא־נתונים של שימוש בלבד**, ללא תוכן הפגישות או תשובות המודל; אין זו טענה על כל לוגי הפלטפורמות החיצוניות. ראו [תיעוד API](apps/api/README.md) לפירוט המגבלות, קבלות לא ודאיות ושגיאות.

## אחסון, סודות ופרסום

כל השמירה המתמשכת של תוכן התיקים מתבצעת ב־Neon דרך API מאומת. הדפדפן מחזיק את העבודה הפעילה בזיכרון העמוד בלבד; האפליקציה אינה שומרת תיקים, טיוטות או אסימוני גישה ב־IndexedDB, ב־localStorage, ב־sessionStorage או ב־cookies. כניסה חדשה טוענת את המאגר לפני פתיחת סביבת העבודה. דמויות הבסיס נוצרות רק כאשר השרת מאשר שהמרחב ריק.

השיחה, הטקסט בשדה הכתיבה, ההצעות, המקורות, ההעדפות והיסטוריית המסמכים נשלחים לשמירת שרת לאורך העבודה. **נשמר בשרת** מופיע רק לאחר אישור השרת. עורך מסמך פתוח דורש לחיצה על שמירת העריכה; עד אז הטקסט שבו הוא זיכרון זמני. אין עבודה מתמשכת ללא חיבור לשרת. ייצוא JSON הוא הורדה מפורשת לפי בחירת המשתמש, ואינו מנגנון שמירה מקומית אוטומטי.

כל כתיבה כוללת `expectedRevision`. התנגשות עוצרת את השמירה במקום לדרוס שינוי ממכשיר אחר. כשל רשת משאיר את העבודה בזיכרון העמוד ומציג ניסיון חוזר; אין הבטחה לשחזור שינוי שטרם קיבל אישור שרת אם העמוד נסגר. בחיבור מחדש משווים לעותק האחרון שאושר באותו עמוד. אין מיזוג אוטומטי. טעינת עותק אחר או ייבוא דורשים בחירה מפורשת כשיש הבדלים.

Neon מחזיק את תמונת המצב העדכנית, כולל כל גרסאות המסמכים וההצעות שבתוכה. אין היסטוריה נפרדת של כל הקלדה או כל תמונות המצב. אין TTL יישומי; מדיניות גיבויים ושימור ספק היא אחריות המפעיל. מזהה המרחב קבוע ואינו נגזר מסיסמת הכניסה. האתר ב־Pages והאתר ב־Vercel טוענים אותו מאגר מאומת.

`.env*`, `.vercel/` ו־`.local/` מוחרגים מ־Git. `.env.example` כולל שמות בלבד. מפתחות השירותים נשארים בשרת. האפליקציה אינה קוראת או משנה עותקי דפדפן שנשארו ממהדורות ישנות; אין להשתמש בהם כבסיס להמשך עבודה. לאחר בדיקת התוכן שבשרת, אפשר לנקות נתוני אתר ישנים דרך הגדרות הדפדפן.
